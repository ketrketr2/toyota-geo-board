# データマン：応答役の見張りと遠隔点検

## 何のための仕組みか

2026-10-26 23:14 に Mac mini が再起動したあと、応答役（launchd: `com.slash.dataman.bot`）は
プロセスとしては動き続けていたが、Slack とのリアルタイム接続（Socket Mode）が「張っては切れる」を
繰り返し、質問をまったく受け取れない状態が 10/30 朝まで続いた（`logs/bot.err.log` に
`on_error invoked (... BrokenPipeError ...)` が大量に出ていた）。

launchd の KeepAlive は「プロセスが落ちたとき」しか再起動しないため、この状態は自動では直らない。
そこで、同期（`com.slash.dataman.sync`、15分ごと）のたびに応答役の様子を見て、
接続切れが続いていれば自動で再起動する見張りを足した。

## 見張り（毎回の同期で自動）

場所: `tools/dataman_ops.py` の `watchdog()`。`tools/dataman_open_sealed.py` の最後から呼ばれる。

1. `logs/bot.err.log` のうち、前回の点検以降に増えた部分を読む
2. 接続切れのエラー（BrokenPipe・ConnectionReset・too_many_websockets など）が 3 件以上あり、
   さらに 30 秒の観察中にも新しく出ていれば「今も切れ続けている」と判断する
3. 回答を作っている最中（応答役の子プロセスに `claude` がいる）なら最大 30 分待つ
4. `launchctl kickstart -k gui/<uid>/com.slash.dataman.bot` で再起動する
   （エラーログが 20MB を超えていれば `bot.err.log.1` に退避してから）
5. 中井さんとデータマンのDMに一言知らせる（6 時間に 1 回まで）

- 再起動は 1 時間に 1 回まで。再起動しても直らないときは、その旨を DM に知らせる
  （Mac mini のネットワーク、または同じ鍵で別の応答役が動いていないかの確認が必要）
- 記録: `logs/watchdog.log`、状態: `secrets/bot_watchdog.json`

## 遠隔点検（必要なときだけ）

`ops/request.json` に依頼を書いて push すると、次の同期で Mac mini が 1 回だけ実行し、
結果を依頼者の公開鍵で封をして `ops/result-<id>.bin` に置く（公開リポジトリでも中身は読めない）。
同じ id は二度実行しない。

```json
{"id": "20261030c", "actions": ["check_now", "slack_probe"],
 "probe_users": ["U04TSJ8H96E"], "requester_pub": "<X25519 公開鍵 base64>"}
```

| 作業 | 内容 |
|---|---|
| `diag` | 読み取りだけの状態点検（起動時刻・プロセス・launchd・ログ末尾など） |
| `restart_bot` | 応答役の再起動（直前の接続数などを記録してから） |
| `check_bot` | 再起動の 60 秒後に、起動ログ・接続エラー・Slack との接続を確認 |
| `check_now` | 待たずに同じ確認 |
| `read_source` | bot.py / answer.py の中身とライブラリの版（トークン類は伏せ字） |
| `slack_probe` | ボットのトークンで読むだけの確認（利用者の状態・ボットのDMの有無と共有状態） |
| `claude_check` | 頭脳（`claude -p`）が短い問いに答えられるか |

ここに無い作業は実行しない。書き込みを伴う作業（再起動を除く）は足さない。
